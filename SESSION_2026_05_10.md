## 1. AI Analyst — What It Is and How It Works

### Architecture
The AI Analyst is a full RAG (Retrieval-Augmented Generation) system. When a user asks a question:

1. The frontend (`RightSidebar.tsx` or `/chat` page) sends the message to `/api/chat` (Next.js proxy)
2. The Next.js proxy forwards it to the Python backend on Fly.io
3. The backend rewrites the query using a fast LLM (Groq `llama-3.1-8b-instant`)
4. Hybrid search (BM25 + vector) retrieves relevant documents from Supabase pgvector
5. Retrieved documents are re-ranked by FlashRank (when available)
6. The LLM generates a streaming response using the documents as context
7. Citations are appended at the end as `[CITATIONS]...[/CITATIONS]` and parsed by the frontend
8. Follow-up question suggestions are generated asynchronously after the response

### LLM Model Routing
| User Role | Model | Provider |
|---|---|---|
| free / student | `llama-3.1-8b-instant` | Groq (free tier) |
| subscriber / professional | `llama-3.3-70b-versatile` | Groq (free tier) |
| advisory / admin | `claude-sonnet-4-6` | Anthropic (paid, requires `ANTHROPIC_API_KEY`) |

**Note:** `ANTHROPIC_API_KEY` is not currently configured. Advisory users fall back to Groq 70B.

**Note:** `BYPASS_AUTH = true` is set in `frontend/middleware.ts` — this means all users are treated as subscribers for the testing phase. When you are ready to enforce paid access, set `BYPASS_AUTH = false`.

### Cost
- **Groq:** Free tier — 14,400 requests/day on 8B model, 1,000 requests/day on 70B model. No cost at current traffic levels.
- **OpenAI:** Used only for embeddings at indexing time (`text-embedding-3-small`). ~$0/month at current scale.
- **Anthropic:** Not configured. $0.

## 2. AI Analyst Fixes Made This Session

### Problem 1: "AI backend is offline" error on production
**Root cause:** The Python backend was never deployed to the cloud. The frontend on Vercel was falling back to `http://localhost:8000` which doesn't exist in the cloud.

**Fix:** Deployed the backend to Fly.io and set `PYTHON_BACKEND_URL=https://vhp-backend.fly.dev` in Vercel environment variables.

### Problem 2: First byte timeout — responses never arrived
**Root cause:** The entire RAG retrieval pipeline ran before the HTTP streaming response started, taking ~30 seconds. Next.js has a 30-second route timeout, so the proxy died before the first byte arrived.

**Fix (backend):** Moved all retrieval work inside the `generate()` async generator in `backend/routers/chat.py` so a keepalive space `" "` flushes as the very first HTTP chunk within 1 second, keeping the connection alive during retrieval.

**Fix (frontend):** Added `export const maxDuration = 60` to `frontend/app/api/chat/route.ts` to extend Next.js route timeout to 60 seconds.

**Fix (frontend):** Strip the leading keepalive space from the first chunk in `RightSidebar.tsx` and `app/chat/page.tsx`.

### Problem 3: AI not suggesting platform tools
**Fix:** Injected the full catalog of all 35 HTR platform tools into the system prompt with their exact URLs. The AI now ends relevant responses with a "🔬 TRY IT IN THE HTR LAB" section containing clickable markdown links.

### Problem 4: "TRY IT IN THE HTR LAB" styling not working
**Root cause:** `String(children)` in ReactMarkdown returns `[object Object]` when the paragraph contains mixed content (text + link elements). The detection check never matched.

**Fix:** Changed detection to use `node?.children?.map((c) => c.value || "").join("")` to extract raw text from the AST nodes directly.

### Problem 5: AI giving copy-paste document answers to general questions
**Root cause:** The RAG system pulled Vermont-specific PDFs (e.g., St. Johnsbury hospital presentation) as the top match for generic questions, and the AI answered entirely from those documents.

**Fix:** Updated `BASE_SYSTEM_PROMPT` in `backend/routers/chat.py` with a hybrid answering approach:
- **General questions** (national topics): Answer from expert knowledge first, add Vermont context from documents at the end only
- **Vermont-specific questions** (Act 167, AHEAD, Vermont Medicaid): Stay document-grounded with explicit citations
- Never treat a single local document as the definitive answer to a national question

## 3. Backend Migration: Railway → Fly.io

### Why We Migrated
Railway's free trial ($5 credit) expired, shutting down the backend. Railway has no hard spending cap — costs could grow unpredictably with 30 testers. Fly.io has a hard spending cap you control, preventing surprise bills.

### Fly.io Setup
- **App name:** `vhp-backend`
- **URL:** `https://vhp-backend.fly.dev`
- **Region:** `sjc` (San Jose, California — close to Supabase US West database)
- **VM:** `shared-cpu-1x`, 1GB RAM
- **Config file:** `backend/fly.toml`
- **Start command:** `/app/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000`

### Environment Variables on Fly.io
Set via `flyctl secrets set`. All secrets from `backend/.env` are configured:
- `GROQ_API_KEY`
- `OPENAI_API_KEY`
- `SUPABASE_DB_URL`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SANITY_PROJECT_ID`
- `SANITY_DATASET`
- `SANITY_API_VERSION`
- `SANITY_API_TOKEN`
- `FRONTEND_URL`

### Auto-Deploy from GitHub
A GitHub Actions workflow at `.github/workflows/fly-deploy.yml` automatically deploys the backend to Fly.io whenever files in the `backend/` folder change on the `main` branch.

**Required GitHub secret:** `FLY_API_TOKEN` — set under Repository Secrets (not Variables).

### Vercel Configuration
`PYTHON_BACKEND_URL=https://vhp-backend.fly.dev` is set in Vercel environment variables for the `vhp` project (Production and Preview environments).

### Fly.io Free Tier Limits
- Free trial: $5 credit (consumed)
- After trial: charged per usage. 1GB RAM machine costs ~$5-7/month
- You can set a hard spending cap in Fly.io account settings
- Monthly limits reset on the 1st of each month
- Requires credit card on file (not charged unless you exceed free limits or your configured cap)

### Cost Summary
| Service | Monthly Cost |
|---|---|
| Fly.io (1GB RAM backend) | ~$5-7/month |
| Groq (LLM inference) | $0 (free tier) |
| OpenAI (embeddings only) | ~$0 |
| Vercel (frontend) | $0 (hobby plan) |
| Supabase (database) | $0 (free tier) |

## 4. Local Development vs Production

### Two Separate Environments

**Local (your Mac):**
- Frontend: `http://localhost:3000`
- Backend: `http://localhost:8000`
- Start frontend: `cd frontend && npm run dev`
- Start backend: `cd backend && source venv/bin/activate && uvicorn main:app --reload --port 8000`
- `--reload` watches for local file changes and restarts automatically
- After pulling new backend code with `git pull`, the `--reload` flag picks up changes automatically

**Production (cloud):**
- Frontend: `https://healthtransformationreview.org` (Vercel)
- Backend: `https://vhp-backend.fly.dev` (Fly.io)
- Frontend deploys automatically when you push to GitHub `main`
- Backend deploys automatically when you push changes to `backend/` folder on GitHub `main`

### Important: Local vs Production Code Sync
When backend code changes are pushed to GitHub, Fly.io gets the new code. Your local backend does NOT get the new code until you run `git pull`. Always run `git pull origin main` before starting your local backend if you want it to match production.

### Git Workflow (You Control All Pushes)
```bash
# After making or reviewing changes:
git add .
git commit -m "your description here"
git push origin main
```
This triggers:
- Vercel to redeploy the frontend (always)
- Fly.io to redeploy the backend (only if `backend/` files changed)

## 5. Role-Based Personalization System

### Problem Being Solved
Users land on the platform, see too much content across 6 pillars, 35 tools, academy, states, and advisory all at once, get overwhelmed, and leave before finding what's relevant to them.

### Solution Architecture
The AI Analyst is the personalization engine. The role picker tells the AI who the user is, and the AI guides them to the exact right content and tools through conversation.

### Component 1: `/welcome` Page
**File:** `frontend/app/welcome/page.tsx`

A clean full-screen role picker with no header, no sidebars. Shows:
- **Top:** "Skip — Show Me Everything" tile (slate/gray background, appears first)
- **Below:** 8 role tiles in a grid (white background, indigo hover)

**Roles:**
1. Hospital / Health System Executive
2. Policy Analyst / Government Official
3. Clinician (MD, NP, PA)
4. Health Economist / Actuary
5. Health Tech Professional
6. Medicaid / Compliance Officer
7. Student / Researcher
8. Investor / Consultant

**On selection:**
- Role saved to `localStorage` as `htr-user-role`
- Role-specific AI greeting saved to `localStorage` as `htr-chat-greeting`
- Chat history cleared
- User redirected to `/chat`

**On skip:**
- `htr-user-role` set to `"all"`
- Generic greeting saved
- User redirected to `/chat`

### Component 2: `/chat` Page — Role-Specific Experience
**File:** `frontend/app/chat/page.tsx`

When the user lands on `/chat` after the welcome flow:
- Greeting from localStorage is loaded and displayed as the first AI message
- 4 dynamic conversation starter cards are shown (see below)
- User can click a card or type their own question
- AI knows their role and tailors all responses accordingly

**Role-specific AI greetings (examples):**
- Executive: "Welcome. I see you're a Hospital / Health System Executive. What are you trying to solve today — financial modeling, VBC readiness, workforce planning, regulatory compliance, or something else?"
- Policy: "Welcome. I see you're a Policy Analyst. What are you working on — Medicaid waiver analysis, Vermont legislation, federal mandates, or something else?"

### Component 3: Dynamic Sanity Cards
**File:** `frontend/app/api/role-content/route.ts`

On every visit to `/chat`, 4 cards are fetched from Sanity CMS:
- **2 cards:** Most recent articles/analyses published in the last 30 days for the user's role pillar
- **2 cards:** Randomly sampled from older articles in that pillar (changes on every visit)
- **Fallback:** If Sanity returns no content, static hardcoded prompts are shown

**Role → Pillar mapping:**
| Role | Pillars Queried |
|---|---|
| Executive | Operations, Economics |
| Policy Analyst | Policy |
| Clinician | Clinical |
| Health Economist | Economics |
| Health Tech | Technology |
| Compliance Officer | Policy |
| Researcher | All pillars |
| Investor | Economics |
| Skip/All | All pillars |

**Content types queried:** `policyAnalysis`, `post`, `caseStudy`

### Component 4: Role Passed to Every AI Request
Every chat message sent to the backend includes the user's role (`userRole` field). The backend injects it into the system prompt:

```
"You are speaking with a Hospital Executive. Tailor your response depth, 
terminology, and tool recommendations accordingly."
```

This makes every AI response role-aware — depth of analysis, terminology, and tool suggestions all adjust based on who is asking.

### Component 5: First-Visit Redirect
**File:** `frontend/components/WelcomeRedirect.tsx`

A client component added to the root layout that checks localStorage on every page load. If `htr-user-role` is not set, the user is redirected to `/welcome`. Skips `/welcome`, `/chat`, `/beta`, `/login`, `/signup`, and `/studio` routes.

5. **Role personalization depth:** Currently the sidebar nav order and homepage content do NOT change based on role — only the `/chat` experience is personalized. Deeper personalization (sidebar reordering, homepage filtering) is a future task.

6. **`htr-chat-greeting` localStorage key:** After the welcome flow, the greeting is consumed once and removed. If the user refreshes `/chat`, they see the dynamic cards (no greeting). This is intentional.
